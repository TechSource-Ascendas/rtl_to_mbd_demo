# From RTL to Model-Based Design

A hands-on, GUI-first walkthrough for experienced Verilog/FPGA engineers who are moving FPGA development to MATLAB and Simulink.
It follows **one** small example, a 4-tap low-pass FIR filter, from the first equation to a bitstream on a Digilent Arty A7-35T.
Every stage is checked **bit for bit** against the previous one.

Start with `Part0_Start_Here.m` in MATLAB R2026a. Every part is a live script with step-by-step screenshots embedded.

---

## If you have been writing RTL for years

**Your hardware judgement stays.**
Registers, pipelining, bit widths, latency, resource use and timing are still your decisions.
A Unit Delay *is* a flop, a Gain *is* a multiplier, and you choose the fixed-point types.
Simulink and HDL Coder don't replace hardware thinking. They remove the hand-translation from algorithm to RTL.

**What changes is when and where you verify:**

| RTL flow | Model-Based Design |
| --- | --- |
| Spec → C/MATLAB reference → hand-written RTL → HDL testbench, four artifacts kept in sync by hand | One Simulink model is the executable spec, the golden reference and the source of the RTL |
| Bugs found in RTL simulation or on the bench | Algorithm verified in floating point first, then bit-true fixed point, before any RTL exists |
| Bit widths chosen from experience while coding | Bit widths proposed from simulated ranges by the Fixed-Point Tool and checked against a tolerance |
| FSMs written as `case` statements and documented separately | FSMs drawn in Stateflow; the diagram is the documentation and generates the `case` code |
| Change a coefficient → edit RTL → re-verify | Change a variable → re-simulate → regenerate |

**What you already have is kept:**
- **Existing Verilog** can be *converted* (`importhdl`), *reused verbatim* (BlackBox/DocBlock), or *verified* against the model (cosimulation). See Part 2.
- **Your Verilog testbench** keeps working. It drives the DUT while Simulink checks the result. See Part 4.
- **Vivado** is still the implementation tool. The custom board in Part 3 is an ordinary IP Integrator block design.

**What the demo shows:**
- **Readable generated Verilog.** It is traceable line by line to the model, and the constant multipliers become shift-and-add (CSD), as you would write them by hand.
- **The Arty A7-35T build passes timing.** At 50 MHz: WNS +13.4 ns, 630 LUTs, 903 FFs, **0 DSPs**. It was programmed and tested on a real board: values written over JTAG read back exactly.
- **The hand-written Verilog matches the model exactly.** It agrees with the Simulink design bit for bit in three independent ways: as an imported model, in cosimulation driven by Simulink, and in cosimulation driven by its own Verilog testbench.

## Requirements
- MATLAB R2026a with Simulink, Stateflow, Fixed-Point Designer, DSP System Toolbox, HDL Coder and HDL Verifier
- HDL Coder Support Package and HDL Verifier Support Package for AMD FPGA and SoC Devices
- AMD Vivado **2024.1**. This is the version R2026a is tested with; the Cosimulation Wizard warns on 2025.1.
- For Part 3 on hardware: a Digilent Arty A7-35T and its micro-USB cable

## Setup
1. Clone into `C:\demo\nexty_basic_simulink`. The cosimulation projects record absolute paths.
   ```
   git clone https://github.com/TechSource-Ascendas/rtl_to_mbd_demo.git C:\demo\nexty_basic_simulink
   ```
   If you use another folder, re-run the Cosimulation Wizard as described in Part 4 (about 5 minutes).
2. Open `Part0_Start_Here.m` and run its setup section. It sets the paths and the Vivado location.
3. Before Part 4, compile the Verilog for Vivado Simulator. In the MATLAB desktop, open `cosim_work/fir4_legacy_cosim.slx` and `cosim_tb_work/tb_cosim_monitor_block.slx`, then double-click the cyan **Generate DLL** block in each. This takes about a minute each.
4. To program the board without rebuilding, open `arty_a7_35t/prebuilt/system_top_wrapper.bit` in the Vivado Hardware Manager, or run the HDL Workflow Advisor tasks in Part 3.
